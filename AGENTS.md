## Code Style Guidelines

### Imports
- Use absolute imports with `@/` prefix (e.g., `@/lib/dexieDB`)
- Group imports in order: React → external libraries → absolute imports → relative imports
- Use named exports for utilities and hooks
- Default export for page components

### TypeScript
- Strict mode enabled in `tsconfig.json`
- Avoid `any` type; use `unknown` or proper types
- Use interfaces for object shapes, types for unions/primitives
- Export all types from `@/types/index.ts`
- Use Zod for runtime validation (schemas defined in `dexieDB.ts`)

### Naming Conventions
- **Components**: PascalCase (e.g., `StudentCard`, `AttendanceTable`)
- **Hooks**: camelCase with `use` prefix (e.g., `useData`, `useTeacherById`)
- **Variables**: camelCase (e.g., `studentList`, `isLoading`)
- **Constants**: SCREAMING_SNAKE_CASE (e.g., `DEFAULT_CACHE_CONFIG`)
- **Database helpers**: Object naming pattern (`studentDB`, `teacherDB`, `attendanceDB`)
- **Interfaces**: PascalCase with descriptive names (e.g., `Student`, `Teacher`, `ScheduleSlot`)

### Component Patterns
- Use `'use client'` directive for client components
- Functional components with TypeScript interfaces
- Props interfaces named `ComponentNameProps`
- Use `React.FC<Props>` for component typing
- Destructure props with defaults for optional values

### Database & State
- Dexie.js for IndexedDB (offline-first)
- Soft delete with `isDeleted`, `deletedAt`, `deletedBy` fields
- Use helper exports: `studentDB`, `teacherDB`, `scheduleDB`, `attendanceDB`
- Cache invalidation after data mutations via `cachedDB.invalidateCache()`
- Zod validation schemas for all entity types

### Error Handling
- Use try/catch with async/await
- Log errors with `console.error` including context
- Return typed results for service operations
- Throw descriptive Error objects for validation failures

### Internationalization
- Default locale: Arabic (ar) with RTL
- Secondary locale: English (en) with LTR
- URL pattern: `/[locale]/[page]`
- Use `useTranslations()` and `useLocale()` hooks
- All UI strings use translation keys (no hardcoded text)

### PWA Features
- Service worker auto-generated by `next-pwa`
- PWA disabled in development (`disable: process.env.NODE_ENV === 'development'`)
- Test PWA with `npm run build && npm start`
- Background sync via `syncQueue` table

### Critical Patterns

**Hydration Safety**:
- Never use `Date()`, `Math.random()` in initial renders
- Use `useEffect` for client-only logic
- Keep loading state structure consistent with loaded state

**Context Usage**:
- Use `useData()` from `@/contexts/DexieDataContext`
- Wrap page content with `DataProvider`
- Access via destructuring: `const { students, teachers, loading } = useData();`

**Data Flow**:
1. Pages → DexieDataContext → Database helpers → IndexedDB
2. Use `cachedDB` functions for read operations with caching
3. Call cache invalidation after mutations

### Directory Structure

```
src/
├── app/              # Next.js App Router pages
├── components/       # Reusable UI components
├── contexts/         # React contexts (use DexieDataContext)
├── hooks/            # Custom hooks
├── i18n/             # Internationalization config
├── lib/              # Core business logic (dexieDB.ts, etc.)
├── services/         # Business logic services
├── types/            # TypeScript interfaces
├── utils/            # Helper functions
└── data/             # Seed/mock data
```

### File Patterns

- `*.tsx` → React components (PascalCase)
- `*.ts` → Utilities, types, helpers (camelCase)
- `messages/*.json` → Translation files (ar.json, en.json, fr.json, ur.json, id.json)

### Database Schema (Dexie.js)

```typescript
// Version 3 schema
this.version(3).stores({
  students: 'id, name, parentPhone, teacherId, status, [status+teacherId], name.lower',
  teachers: 'id, name, email, phone, status, [status+name]',
  schedule: 'id, teacherId, day, [teacherId+day], [day+startTime]',
  attendance: '++id, studentId, date, [studentId+date], [date+status]',
  syncQueue: '++id, type, action, timestamp, [type+timestamp]'
});
```

### Common Errors & Fixes

| Error | Fix |
|-------|-----|
| "useData must be used within a DataProvider" | Import from `@/contexts/DexieDataContext` |
| Hydration mismatch | Use `useEffect` for Date/Math operations |
| PWA not working in dev | Expected; test with production build |
| Type errors | Run `npx tsc --noEmit` to check |
